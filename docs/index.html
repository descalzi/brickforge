02 / THE PIPELINE

The object comes first.

  1. Describe the object

    A language model writes an object intent: overlapping shapes at real-world size, with roles, colours and openings. It never names parts or studs.

  2. Mass and detail

    The engine picks the scale, rasterises the shapes on the stud grid, hollows them, tiles every layer with real elements and swaps in slopes and wheel assemblies where they fit.

  3. Check the assembly

    Inspect the mating graph, body envelopes, support projection and nominal approach checks. Unsupported requirements and unverified physics stay visible.

  4. Build on the result

    Inspect individual steps, edit components, save browser-local revisions, and export LDraw, the parts list, a full report and an illustrated instruction booklet.

03 / WHAT THE RESULT MEANS

A checked candidate,
with its limits in view.

The engine always returns its best model and reports where it differs from the description: shape match, components too small for the build size, colours changed to join pieces. Fine detail is limited by the stud grid; curved surfaces are stepped.

Connection checks are nominal. The support calculation uses a simplified volume proxy; approach checks exclude studs, cavities, deformation and hand access. Physical clutch, strength, rolling performance and structural stability require further evidence.

No hosted language service is bundled. Copy the prompt into any chat assistant, use an on-device browser model or a gateway you configure. Construction itself stays in your browser.
